# 강의 슬라이드 고도화 — 2단계

부록 이미지 16장이 그 자체로 예시 수준이므로, 기존 21개 강의 항목도 그 수준까지 올린다.
1단계(공통 렌더러 + 8개 슬라이드)는 2026-09-27에 끝났다. 여기서는 남은 것과,
1단계에서 드러난 함정들을 적는다.

## 1단계가 바꾼 것

| 슬라이드 | 이전 | 이후 |
|---|---|---|
| 04 ai-agent | 슬라이드 문구를 그대로 점등하던 시뮬레이션 | 이 강의에서 실제로 겪은 실패(부록 이미지 16장 실수 삭제)와 `git restore`로 되돌리는 과정 |
| 07 architecture | `프론트엔드 ↔ API ↔ 백엔드 ↔ DB` 화살표 | 실제 메모장 목업 + 저장하기를 누르면 4단계가 차례로 켜지며 각 단계의 코드가 나옴 |
| 08 ui-terms | GUI/TUI/CLI 각각 설명 카드 | 같은 동작(메모 저장)을 세 방식으로 실제 화면으로. 아무 칸이나 누르면 셋이 같은 동작임을 표시 |

외부 의존성 없음, 오프라인, HTML 조각은 전부 `esc()` 통과.

## 2단계 남은 것

**DBML → ERD 실시간 렌더 (슬라이드 9).** 요청은 "PRD 구조 + DBML 기준으로 실시간 움직이는 ERD + 쉬운 용어와 실제 SQL 용어를 나란히"였다.
현재 엔진은 노드 그래프 스텝 재생기라 DBML을 해석도, 그림을 그리지도 못한다. 필요한 것:

- DBML 파서 (Table / Ref / Note 최소)
- 레이아웃 엔진 (박스 배치 + 관계선 라우팅)
- 빌드 전후를 보여주는 재생 컨트롤

`flowRail`과 `gitGraph`가 기반이 되지만 별도 서브시스템이다. 1단계 목업이 슬라이드 7·8을 먹고 남은 용량이 여기다.

## 1단계에서 드러난 함정 — 같은 사고를 되풀이하지 않기

**① 장면 `narration`은 자료함 매칭의 키다.**
슬라이드 4의 narration을 세로 줄여서(높이 확보 목적) "AI는 질문에 답하지만, Agent는 목표를 받고 직접 실행합니다. 그런데 AI는 자주 틀립니다."로 바꾸자,
`prose-attribution.md`에 대한 변경안이 0건이 됐다. 자료함은 이 문장을 장면 문장과 대조해 변경을 만들기 때문이다.
`smoke-v4-shell`의 `qa21_proseChangeCarriesSourceName`이 이걸 잡아냈다.
**narration은 성능 문제가 아니라 제품 기능의 입력이다.** 줄이고 싶으면 화면(렌더러)을 줄여라.

**② 스테이지는 `overflow:hidden`이라 넘친 걸 알려주지 않는다.**
`.stage`가 잘라 버리므로 `documentElement.scrollHeight`는 늘 정상이라고 나온다.
그래서 `safety`와 `chat-terminal`은 시뮬레이션 버튼이 잘린 채 한참 배포돼도 아무 테스트가 잡지 못했다.
지금은 `smoke-v4-lecture`의 `qa22_allScenesRender`가 **마지막 자식 요소의 하단**을 스테이지와 비교한다.

**③ 창 크기 1366×768은 뷰포트가 아니다.**
프레임을 포함한 크기라 실제 뷰포트는 창 관리자 유무에 따라 703이 되기도 768이 되기도 했다.
같은 테스트가 WSL에서 4개 슬라이드 초과, xvfb에서 0개로 판정했다.
두 스모크와 `capture-scenes` 모두 `useContentSize: true`로 고정했다.

**④ 코드를 `pre`에 넣을 때 줄을 `\n`으로 잇지 마라.**
`.tl`이 `display:block`이면 개행 텍스트 노드가 각 줄에 빈 줄 상자를 하나씩 더 만든다.
모든 코드 블록이 정확히 2배 높이가 되었고, 겉으로는 "Stage-CUT"으로만 보였다. 지금은 `join('')`이다.

**⑤ 슬라이드 높이를 맞출 때는 렌더러를 줄이지 말고 대본을 지켜라.**
높이 부족 → `narration`을 줄이기 → ①로 연결. 이 순환이 이번 작업에서 가장 위험했다.

**⑥ 검사기가 문자열과 코드를 구분 못 하면 그건 검사기의 문제다.**
`SCENE_RENDERERS 안에 타이머가 있습니다` 경고가 슬라이드 18의 `setInterval(collect, ...)` **코드 샘플**에 걸렸다.
가드를 약화시키는 대신 문자열 리터럴을 지운 뒤 검사하도록 바꿨고, 실제 `setTimeout(` 호출은 여전히 잡힌 것을 확인했다.
